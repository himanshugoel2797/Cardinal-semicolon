# rtl8139

> Lisp driver for the Realtek RTL8139 NIC: resets, configures, and polls the device, forwarding received frames to and accepting transmit frames from [corenetwork](../servers/corenetwork.md).

| | |
|---|---|
| **Source** | `lisp/drivers/rtl8139.clp` |
| **Kind** | driver |
| **Bound by** | `lisp/init.clp` — `(bring-up #x10ec #x8139 rtl8139-init)` via `pci-find-all`; one driver instance per enumerated device |
| **Registers with** | [corenetwork](../servers/corenetwork.md) via `(send net (list 'register-nic mac tx-ctx))` |
| **Capabilities** | `sys-mmio` (`mmio-map`, `dma-alloc-32`), `sys-pci` (`pci-find`, `pci-assign-bars`), `driver-util` |

## Overview

The RTL8139 is a legacy Fast-Ethernet NIC.  Its registers live in a 256-byte
MMIO window (BAR1), and it DMAs using 32-bit physical addresses only — all DMA
buffers **must** be below 4 GB (`dma-alloc-32` is mandatory).  The device has
no MSI capability; it drives only a legacy PCI INTx line.  Rather than build a
PCI-INTx → `irq-wait` bridge, this driver polls the receive ring from a
dedicated spawned context that `sleep`s between drains; `sleep` yields the
scheduler, so other contexts run between polls.  The interrupt mask register
(`IMR`) is left at zero — no interrupts are raised.

The driver is pure transport: it owns DMA buffers, a 64 K receive ring, and
four TX descriptor slots, but all Ethernet/ARP/IP framing resides in
[corenetwork](../servers/corenetwork.md).  On success, `rtl8139-init` spawns
two restricted contexts (TX and RX) and sends a `register-nic` message to the
network service.

RX uses the standard CAPR/CBR-driven circular-buffer extraction: the device
writes received frames into a flat ring prefixed by a 4-byte header, and the
driver drains them in `rx-extract!` (see [RX Ring](#rx-ring)).

## Initialization

`init.clp` calls `rtl8139-init` inside a `bring-up` helper that iterates over
all PCI devices matching VID `0x10EC` / DID `0x8139` via `pci-find-all`.  Each
call receives the corenetwork service handle and the ECAM pointer for one
device.

```scheme
(rtl8139-init net dev-ecam)
```

- `net` — the corenetwork context handle (obtained from `start-network-service`).
- `dev-ecam` — the ECAM config-space mapping for this RTL8139 device; `#f` if no device is present.

Returns `'ok` on success or `#f` (with a diagnostic on the console) on any
failure.  `rtl8139-init` must run inside a spawned context because it calls
`wait-until` (which yields) during the reset-settle loop.

### Bring-up sequence

1. Maps the ECAM page and enables memory + bus-master in the PCI command register.
2. Reads BAR1 base; if it is zero, calls `pci-assign-bars` and re-reads.
3. Maps the 256-byte MMIO register window.
4. Writes `CONFIG1 ← 0` (power-on), then `TX-CMD ← CMD-RST (#x10)`, and
   waits (bounded, 100 ms) for the RST bit to self-clear.
5. Allocates the RX ring buffer (`RX-BUF-SIZE` = 66,032 bytes, `<4 GB`) and
   four TX slot buffers (`TX-SLOT-SIZE` = 2,048 bytes each, `<4 GB`).
6. Programs `RBSTART` and the four `TX-ADDR(i)` registers with the physical
   addresses of those buffers.
7. Sets `RCR` to accept physical-match, multicast, and broadcast frames with
   WRAP mode and a 64 K ring (`RCR-VALUE`).
8. Sets `TX-CFG` preserving inter-frame-gap bits, with max DMA burst 1024 (6 << 8).
9. Enables RX and TX by writing `CMD-RXEN | CMD-TXEN` to `TX-CMD`.  `IMR`
   remains 0 (no interrupts).
10. Spawns the TX context and the RX poll context.
11. Sends `(register-nic mac tx-ctx)` to `net`.

## MMIO Register Map

All offsets are relative to the BAR1 base address.  The window is `#x100` bytes.

| Constant | Offset | Width | Description |
|---|---|---|---|
| `IDR0` | `#x00` | u8×6 | MAC address bytes |
| `RBSTART` | `#x30` | u32 | RX ring buffer start (physical, <4 GB) |
| `TX-CMD` | `#x37` | u8 | Command register (RST, RXEN, TXEN, BUFE) |
| `CAPR` | `#x38` | u16 | Current address of packet read (host write-back pointer) |
| `CBR` | `#x3A` | u16 | Current buffer address (device write pointer) |
| `IMR` | `#x3C` | u16 | Interrupt mask — left at 0 (polling mode) |
| `ISR-REG` | `#x3E` | u16 | Interrupt status |
| `TX-CFG` | `#x40` | u32 | Transmit configuration |
| `RCR` | `#x44` | u32 | Receive configuration |
| `CONFIG1` | `#x52` | u8 | Power management (set 0 to power on) |
| `MEDIA-STATUS` | `#x58` | u8 | Media status |
| `TX-ADDR(i)` | `#x20 + i×4` | u32 | TX descriptor i buffer physical address (i = 0–3) |
| `TX-STS(i)` | `#x10 + i×4` | u32 | TX descriptor i status / length |

## RX Ring

The device uses a flat circular byte buffer.  The driver configures a 64 K ring
(`RX-RING-LEN` = 65,536) with an additional 1,516-byte WRAP overrun slop
(`RX-BUF-SIZE` = 66,032).  Each received frame is prefixed by a 4-byte header:

```
offset 0: u16  status  (bit 0 = ROK — receive OK)
offset 2: u16  length  (frame + 4-byte Ethernet CRC)
offset 4: u8[] frame bytes
```

The next header begins at the dword-rounded byte following the frame (including
the 4-byte length field).  The host advances `CAPR` by writing `(next-off − 16)
& 0xFFFF` — the device applies a 16-byte CAPR quirk.

The RX poll context drains the ring with `rx-extract!` every `RX-POLL-NS`
(1 ms), then calls `(sleep RX-POLL-NS)` to yield.  Only frames with `ROK` set
and at least 14 bytes (minimum Ethernet header) are forwarded.

## TX Descriptors

Four TX descriptor slots are used in round-robin order (`NTX` = 4, slot size
`TX-SLOT-SIZE` = 2,048 bytes).  Writing the frame length (low 13 bits) into
`TX-STS(i)` clears the OWN bit and starts the DMA.  The device sets
`OWN | TOK` when the transmit completes.

`tx-fill!` waits up to 100 ms for the selected slot to become idle (the size
field of `TX-STS` reaching zero) before copying the frame and kicking the
device.

## TX Context Protocol

The spawned TX context loops on `recv`.  The network service sends transmit
requests as:

```scheme
(send tx-ctx (list 'tx frame len))          ; fire-and-forget
(send tx-ctx (list 'tx frame len reply-ctx)) ; with optional ack
```

- `'tx` — the message tag.
- `frame` — a `bytes` object containing the raw Ethernet frame.
- `len` — byte count of the valid frame data.
- `reply-ctx` (optional) — if present, the TX context sends `(tx-done)` to it
  after `tx-fill!` returns.

The TX context is the handle registered with corenetwork as the NIC's transmit
path.

## RX Context Behaviour

The spawned RX context loops indefinitely:

```scheme
(rx-extract! regs rxbuf off-cell
  (lambda (foff flen)
    (send net (list 'rx (copy-bytes rxbuf foff flen) flen))))
(sleep RX-POLL-NS)
```

Each good frame is snapshot-copied out of the recycled ring buffer before
forwarding so the ring byte can be immediately reused by the device.

## Exported Functions

These are exported by the module and may be used directly (e.g. in unit tests)
without hardware.

### `(rx-parse-one rxbuf off)`

Pure function.  Parses the 4-byte RX header at byte offset `off` in `rxbuf`.

- `rxbuf` — the receive ring `bytes` object.
- `off` — byte offset of the header within the ring.

Returns `(list frame-off frame-len next-off)`:
- `frame-off` — byte offset of the first frame byte (`off + 4`).
- `frame-len` — frame length in bytes (header length minus the 4-byte CRC).
- `next-off` — dword-rounded offset of the next header, wrapped modulo
  `RX-RING-LEN` (64 K).

### `(rx-extract! regs rxbuf off-cell handler)`

Drains every frame currently in the ring.  For each frame with `ROK` set and
at least 14 bytes, calls `(handler frame-off frame-len)`.  Advances the
read-offset cell and writes `CAPR` after each frame.  Returns `'drained` when
the ring is empty (`CMD-BUFE` set in `TX-CMD`).

- `regs` — the MMIO register `bytes` mapping.
- `rxbuf` — the DMA receive buffer `bytes`.
- `off-cell` — mutable cell holding the current ring read offset.
- `handler` — `(lambda (frame-off frame-len) …)`

### `(tx-fill! regs txbufs free-cell frame len)`

Copies `len` bytes from `frame` into the next available TX slot and kicks the
device.  Waits up to 100 ms for the chosen slot to become idle.  Returns
`'sent` on success or `#f` if `len` is out of range (`<= 0` or `> TX-SLOT-SIZE`).

- `regs` — MMIO register `bytes`.
- `txbufs` — list of four DMA TX slot `bytes` objects.
- `free-cell` — mutable cell holding the next slot index (0–3).
- `frame` — source `bytes` object.
- `len` — byte count.

### `(rtl8139-init net dev-ecam)`

Driver entry point; documented under [Initialization](#initialization).

## Notes / Gotchas

**DMA must be below 4 GB.** The RTL8139 has a 32-bit DMA address bus.
`dma-alloc-32` is used throughout; if the allocator returns a buffer at or
above `#x100000000`, init aborts.

**No MSI; polling only.** `IMR` is left at zero — the device never raises an
interrupt.  The 1 ms poll interval is a balance between latency and scheduler
overhead.  A future PCI-INTx → `irq-wait` bridge would eliminate the sleep loop
without structural changes (the spawned-context shape already matches a parked
`wait-for-irq` loop).

**CAPR quirk.** The device applies a 16-byte internal bias to `CAPR`; the
driver always writes `(next-off − 16) & 0xFFFF`.

**RX-handler re-entrancy rule.** Frames are forwarded to corenetwork via
`(send net (list 'rx …))`.  The network service runs the stack synchronously and
may trigger a reply (ARP response, ICMP echo reply, or a UDP/RDT service that
answers) that re-enters this driver's TX path.  The RX poll context must not hold
any device lock across the `send` call.  This driver holds no explicit lock during
the forward, so it is safe; any future refactor that introduces locking must
preserve this property to avoid self-deadlock.  See
[message passing](../concepts/message-passing.md) for the wider rule.

**WRAP slop.** An overrunning frame (one that straddles the ring end) is allowed
to spill into the 1,516-byte slop region (`RX-BUF-SIZE` exceeds `RX-RING-LEN`
by 16 + 1,500 bytes) rather than wrapping mid-frame; `RCR` bit 7 (`WRAP`) is
set.

**BAR1 auto-assignment.** If firmware left BAR1 unassigned (base reads as
zero), `pci-assign-bars` is called to place all BARs and open bridge windows
up to the root bus.

**QEMU validation status.** The RTL8139 is not instantiated by the default QEMU
machine (`virtio-net` is the preferred NIC); pass `-device rtl8139` to exercise
this driver.  RX reception from this driver has not been validated end-to-end in
QEMU; TX has been confirmed functional.
