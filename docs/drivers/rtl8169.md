# rtl8169

> Realtek RTL8168/8111 gigabit NIC driver: descriptor-ring + MSI-driven transport that registers with [corenetwork](../servers/corenetwork.md).

## Overview

The rtl8169 driver targets the RTL8168/8111 "C+" family of Realtek gigabit NICs.
Unlike the RTL8139, which uses a flat byte ring and legacy INTx, the 8168 uses
16-byte DMA **descriptor rings** with 64-bit buffer addresses and signals via
**MSI** rather than a legacy interrupt line.  The overall shape is therefore
the same as `virtio-net`: a descriptor ring plus an MSI-driven RX pump.

The driver is pure transport.  It handles DMA, PHY power-up, and frame I/O;
all Ethernet/ARP/IP framing lives in corenetwork.  On success it spawns two
restricted contexts (a TX loop and an RX MSI pump) and sends a
`(register-nic mac tx-ctx)` message to the corenetwork service handle.

**QEMU caveat:** QEMU does not emulate an RTL8168/8111 (`-device rtl8168` does
not exist).  This driver runs only on real RTL8111G silicon.  The pure
descriptor helpers (`tx-desc-build!`, `rx-desc-init!`, `rx-desc-consume`,
`read-mac`) are factored so that a test harness can drive them over mock byte
buffers without hardware.

Ring geometry: **32 RX descriptors × 2048-byte buffers** and **32 TX
descriptors × 2048-byte buffers** — roughly 64 KiB of packet buffers and 512 B
of descriptors per direction.  Each DMA buffer is allocated with `dma-alloc`
(not `dma-alloc-32`; the 8168 handles 64-bit addresses throughout).

## Initialization

`init.clp` calls `rtl8169-init` once per enumerated 8168 device:

```scheme
(rtl8169-init net dev-ecam)
```

- `net` — the corenetwork service handle (obtained from `(start-network-service)`).
- `dev-ecam` — the ECAM config-space base for this PCI device, as returned by
  `pci-find-all`.  If `#f`, the driver logs and returns `#f` immediately.

### Bring-up sequence

1. **Memory-space enable + bus-master** (`pci-enable-mem-bus-master!` on the
   config space) before any BAR or MMIO access — with memory-decode off, every
   register reads back `0xFF` and the software-reset bit never clears.
2. **D3→D0 power transition** (`power-on-d0`): walks the PCI capability list to
   the Power-Management capability (id `0x01`) and clears the low two
   `PowerState` bits in PMCSR; waits 10 ms for the BARs to become live.
3. **BAR2 register window**: reads the 64-bit BAR2 base.  If the firmware left
   it unassigned (`0`), calls `pci-assign-bars` to self-assign BARs and open
   every upstream bridge window, then re-reads BAR2.  Maps `0x100` bytes via
   `mmio-map`.
4. **Software reset** (CMD-REG bit 4, `CMD-RST`): bounded 100 ms wait via
   `wait-until`; logs and returns `#f` on timeout.
5. **PHY wake** (`phy-wake`): writes MII registers via the indirect PHYAR
   interface to select PHY page 0 and clear the power-down bit.  A 20 µs
   inter-cycle settle is required on real 8168G silicon; back-to-back MII
   accesses can otherwise leave the PHY powered down and prevent link.
6. **DMA allocation**: four buffers via `dma-alloc`:
   - `rxring` — `NRX × DESC-SIZE` bytes (512 B) for RX descriptors.
   - `txring` — `NTX × DESC-SIZE` bytes (512 B) for TX descriptors.
   - `rxbuf`  — `NRX × PKT-SIZE` bytes (64 KiB) for RX packet data.
   - `txbuf`  — `NTX × PKT-SIZE` bytes (64 KiB) for TX packet data.
7. **Ring initialization** (`rx-ring-init!`, `tx-ring-init!`): descriptor `i`
   points at slot `i` of the corresponding packet buffer; EOR is set on the
   last descriptor; all RX descriptors are handed to the NIC (OWN=1).
8. **Hardware configuration** (in the order the BSD `re` driver uses):
   - C+ command register (`CPLUS-CMD`) programmed **first** (BSD requirement).
   - Config area unlocked (`_93C56-CMD = 0xC0`), then re-locked (`0x00`).
   - RX config (`RCR`): FIFO/DMA/burst settings + all-types accept mask.
   - TX config (`TX-CFG`): max-rate and unlimited burst.
   - Missed-packet counter (`0x4C`) zeroed (statistics only).
   - `MAX-TX` set to `PKT-SIZE / 128`.
   - RX descriptor ring physical address written to `RX-ADDR`/`RX-ADDR+4`.
   - TX descriptor ring physical address written to `TX-ADDR`/`TX-ADDR+4`.
   - RXDV gate cleared (MISC-REG bit `0x00080000`).
   - `MAX-RX` set to `PKT-SIZE`.
   - CONFIG1 bit `0x20` set (driver-loaded marker).
9. **MSI setup** (`pci-setup-msi`): called **after** reset (reset clears the
   MSI-X table which lives in NIC memory); returns `#f` on failure (driver
   aborts with a log message).
10. **Undocumented 8168G chip poke**: `regs[0xE2] |= 0x5100`, matching BSD `re`.
11. **RX+TX enable**: CMD-REG bits `CMD-RXEN | CMD-TXEN`.
12. **TX context** spawned: a `spawn-restricted` loop that handles `(tx frame
    len [reply-ctx])` messages.
13. **RX MSI pump** spawned: a `spawn-restricted` loop that mask/ack/sweep/
    unmask on each MSI wake.
14. **`(register-nic mac tx-ctx)`** sent to `net`.
15. **IMR enabled last**: ISR cleared (`0xFFFF`), then `IMR` set to
    `INTR-ROK | INTR-TOK`.  Enabling the NIC's interrupt generation last
    (after the MSI cap is armed and the pump exists) prevents an
    edge-triggered MSI for an already-pending frame from being lost.

Returns `'ok` on success, `#f` on any failure (no device, reset timeout, BAR
failure, DMA allocation failure, MSI setup failure).

## Message protocol

The driver does not expose a public message protocol of its own.  The two
spawned contexts have restricted capability sets and are internal.

### TX context — internal

The TX context (handle passed to corenetwork as `tx-ctx`) receives:

```scheme
(tx frame len)
(tx frame len reply-ctx)   ; optional: sends (tx-done) to reply-ctx on completion
```

- `frame` — a `bytes` object carrying the raw Ethernet frame.
- `len` — frame byte count (must be `> 0` and `≤ 2048`; otherwise the send is
  silently dropped).
- `reply-ctx` — optional; if present, `(tx-done)` is sent to it once the
  descriptor has been kicked.

On each send, the driver waits up to 100 ms for the current slot's prior
transmission to drain (`tx-desc-idle?`).  If the NIC has not released the
descriptor within the timeout, the packet is **dropped** rather than
overwriting a buffer the NIC is still reading.

### RX MSI pump — internal

The RX pump parks on `msi-wait` between wakes.  On each MSI:

1. Mask `IMR` (disable interrupts at the NIC).
2. Write-1-to-clear `ISR-REG` (acknowledge all pending causes).
3. Sweep the RX ring (`rx-sweep!`): for each NIC-filled descriptor, copy the
   frame out of `rxbuf` and send `(rx bytes len)` to the corenetwork service.
4. Re-arm each consumed descriptor (`rx-desc-rearm!`) handing the buffer slot
   back to the NIC.
5. Re-enable `IMR` (`INTR-ROK | INTR-TOK`).

The mask/ack/service/unmask sequence follows the BSD `re` driver and re-arms
the edge-triggered MSI for any frame that arrived between the sweep and the
unmask.

**RX-handler locking rule:** `rx-sweep!` calls `(send net ...)` to forward
each received frame to corenetwork, which runs the stack synchronously.  A frame
that triggers a reply (ARP, ICMP, or a UDP/RDT service that answers) causes
corenetwork to re-enter this driver's TX path.  The RX pump must **never** hold
any lock across `(send net ...)` or it will self-deadlock on the first
reply-triggering frame.  The current implementation holds no locks (the RX pump
is the sole writer to the ring state it touches).  See
[message passing](../concepts/message-passing.md) for the wider rule.

## Exported functions

The module exports the following names (declared in `(define-module rtl8169 (export ...))`):

### `(rtl8169-init net dev-ecam)`

Main entry point.  See [Initialization](#initialization).

### `(read-mac regs)`

```scheme
(read-mac regs)   ; → '(b0 b1 b2 b3 b4 b5)
```

Reads the six MAC address bytes from IDR0–IDR5 of the MMIO register window
`regs`.  Pure over the `bytes` buffer — usable in a self-test with a mock
buffer pre-stamped with the expected values.

### `(tx-desc-build! ring i len last?)`

```scheme
(tx-desc-build! ring i len last?)   ; → (void), mutates ring
```

Stamps TX descriptor `i` in `ring` with dword0 = `OWN | FS | LS | len`
(plus `EOR` if `last?` is true).  Pure over the buffer; a self-test can
assert the resulting control word.

### `(rx-desc-init! ring i buf-phys last?)`

```scheme
(rx-desc-init! ring i buf-phys last?)   ; → (void), mutates ring
```

Initializes RX descriptor `i`: sets `OWN=1`, `EOR` if `last?`, `frame_length`
preset to `PKT-SIZE`, buffer address to `buf-phys`.  Pure.

### `(rx-desc-consume ring i)`

```scheme
(rx-desc-consume ring i)   ; → frame-length (integer) | #f
```

Reads descriptor `i` dword0.  Returns the frame length (bits 13:0) when the
NIC has filled the buffer (`OWN=0`); returns `#f` when the descriptor is still
NIC-owned (`OWN=1`, buffer empty).  Pure.

## Notes / gotchas

- **Real hardware only.** QEMU has no `rtl8168` device.  CI smoke tests
  therefore cannot exercise this driver end-to-end; the exported pure helpers
  (`read-mac`, `tx-desc-build!`, `rx-desc-init!`, `rx-desc-consume`) enable
  unit-level coverage without hardware.

- **`pci-assign-bars` may be required.** An onboard RTL8111G that firmware
  never initialized (e.g. behind a PCIe root port not touched at boot) often
  has unassigned BARs and a closed bridge window.  `rtl8169-init` detects this
  (BAR2 reads back `0`) and calls `pci-assign-bars` to self-assign BARs and
  open every bridge window up to the root bus before mapping the register window.

- **`power-on-d0` before any MMIO.** The NIC sits in D3hot when firmware hasn't
  touched it: the device ID is visible in config space but every MMIO register
  reads back `0xFF`.  The D3→D0 transition and the 10 ms settle must complete
  before the software-reset bit is written.

- **`pci-enable-mem-bus-master!` before BAR reads.** With memory-space decode
  disabled the reset bit appears never to clear; bus-mastering must be enabled
  for DMA to work.

- **MSI setup after reset.** The RTL8168 MSI-X table lives in NIC memory.  A
  software reset clears it.  `pci-setup-msi` is therefore called after the
  reset completes, not before.

- **PHY inter-cycle settle.** `phy-write` sleeps 20 µs after each PHYAR cycle.
  Omitting this on real 8168G silicon causes back-to-back MII accesses to
  arrive before the prior write takes effect, leaving the PHY powered down.
  Harmless on QEMU; load-bearing on hardware.

- **TX bounded-wait + drop.** If the NIC has not released a TX descriptor
  within 100 ms the packet is dropped rather than overwriting a buffer the NIC
  may still be reading.  This is the same rule documented in `notes/AUDIT.md`
  for the rtl TX path.

- **8168G undocumented chip poke.** `regs[0xE2] |= 0x5100` is applied just
  before enabling RX/TX, matching BSD `re`.  No public documentation for these
  bits exists; they are required on real 8168G silicon.

- **C+ register programmed first.** The BSD `re` driver documents that the C+
  command register (`CPLUS-CMD` at `0xE0`) must be written before all other
  configuration registers, otherwise MAC-statistics mode does not engage
  correctly.
