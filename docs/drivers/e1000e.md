# e1000e

> Intel e1000 / e1000e gigabit Ethernet driver (82540 + 82574 families): legacy descriptor rings with a poll-based RX pump, registering with [corenetwork](../servers/corenetwork.md).

## Overview

The e1000e driver targets Intel's classic gigabit MACs using the **legacy
16-byte descriptor ring** model, which both the 82540EM (`-device e1000`) and the
82574L (`-device e1000e`) speak.  Like the other NIC drivers it is pure
transport: DMA + frame I/O here, all Ethernet/ARP/IP framing in
[corenetwork](../servers/corenetwork.md).

Its distinguishing feature is a **poll-based RX pump**.  The two target families
deliver receive interrupts very differently — the 82540 has *no MSI capability*
at all (legacy INTx only), and the 82574 routes RX through MSI-X + the `IVAR`
register, which this driver does not program.  Rather than special-case each, the
RX pump **polls the descriptor ring** on a short interval (`RX-POLL-NS`, 2 ms);
when an MSI handle does exist it parks on the interrupt *with* that poll timeout,
so a real interrupt wakes it immediately but an unrouted one is still serviced
within the interval.  This makes RX work on both QEMU variants and on real
hardware regardless of interrupt wiring.

Ring geometry: **32 RX descriptors** and **32 TX descriptors**, each with
**2048-byte** packet buffers.  All DMA is via `dma-alloc-32` (sub-4 GiB
physical), since the firmware-less BARs are placed low and the legacy
descriptors carry 64-bit addresses with the high dword left 0.

## Initialization

`init.clp` calls `e1000e-init` once per enumerated device:

```scheme
(e1000e-init net dev-ecam)   ; → 'ok, or #f on failure
```

- `net` — the corenetwork service handle.
- `dev-ecam` — the device's ECAM config-space base from `pci-find-all`.

`e1000e-init` runs the blocking bring-up inside a spawned context.

### Bring-up sequence

1. **Memory-space + bus-master enable** before any MMIO access.
2. **BAR0 register window** (128 KiB) via `mmio-map`; `pci-assign-bars` first if
   the BAR reads back 0 (onboard NIC behind a closed bridge window).
3. **Software reset** (`CTRL.RST`), bounded ~1 s wait for the bit to self-clear.
4. **Mask interrupts** (`IMC = 0xFFFFFFFF`), set **link up** (`CTRL.SLU | ASDE`).
5. **Read the MAC** from `RAL0`/`RAH0` (`read-mac`).
6. **Allocate** RX/TX descriptor rings and packet buffers (`dma-alloc-32`).
7. **Program the RX ring**: `RDBAL`/`RDBAH`/`RDLEN`, `RDH = 0`, `RDT = NRX-1`,
   then `RCTL = EN | BAM | SECRC | BSIZE-2048`.
8. **Program the TX ring**: `TDBAL`/`TDBAH`/`TDLEN`, `TDH = TDT = 0`, `TIPG`,
   then `TCTL = EN | PSP | CT | COLD`.
9. **MSI (optional)**: `pci-setup-msi` — a `#f` result (no MSI cap, e.g. the
   82540) is **not** fatal.
10. **Spawn the TX context** and the **RX poll pump**.
11. **`(register-nic mac tx-ctx)`** to corenetwork.
12. **Enable RX interrupts last** — `IMS = RXT0 | RXO | LSC`, but **only when an
    MSI handle exists** (an unhandled INTx on the no-MSI path could storm; the
    poll covers delivery either way).

Returns `'ok`, or `#f` on no device / reset timeout / BAR failure / DMA failure.

## Message protocol

The driver exposes no public message protocol; its two spawned contexts are
internal (restricted capability sets).

### TX context — internal

```scheme
(tx frame len)
(tx frame len reply-ctx)   ; optional: sends (tx-done) to reply-ctx on completion
```

Copies the frame into the TX DMA buffer, posts a legacy TX descriptor
(`EOP | IFCS | RS`), and waits up to 100 ms for the NIC to set the descriptor
`DD` bit before reusing the slot — dropping the packet on timeout rather than
overwriting a buffer the NIC may still be reading.

### RX poll pump — internal

A `spawn-restricted` loop that, each pass: reads `ICR` (read-to-clear),
**sweeps** the RX ring (`rx-sweep!`) forwarding each NIC-filled descriptor
(`DD` set) as `(send net (list 'rx (copy-bytes …) len))` and advancing `RDT`,
then either parks on `(msi-wait msi (msi-count msi) RX-POLL-NS)` (MSI present) or
`(sleep RX-POLL-NS)` (no MSI) before looping.

**RX-handler locking rule:** the pump forwards each frame to corenetwork, which
runs the stack synchronously and may re-enter this driver's TX path for an
ARP/ICMP reply.  The pump must never hold state across `(send net …)`; it is the
sole writer of the ring/`RDT` state it touches and copies each frame out first.
See [message passing](../concepts/message-passing.md).

## Exported functions

Pure helpers exported for the host unit test (`libs/lisp/test/test_e1000e.c`):

### `(read-mac regs)`

Reads the six MAC bytes from `RAL0`/`RAH0` of the MMIO window `regs`.

### `(tx-desc-build! ring i len)` / `(tx-desc-done? ring i)`

Stamp a legacy TX descriptor (length + `EOP|IFCS|RS` command) and test its `DD`
status bit.

### `(rx-desc-status ring i)` / `(rx-desc-len ring i)` / `(rx-desc-eop? ring i)`

Read an RX descriptor's status byte, frame length, and end-of-packet bit.

## Notes / gotchas

- **Poll-based RX is deliberate.** The 82540 has no MSI capability, and the
  82574 needs MSI-X `IVAR` routing this driver doesn't program — a pure
  interrupt-driven pump would sleep forever on both.  Polling every 2 ms makes RX
  work everywhere; the MSI, when present, just removes the latency.

- **Both families, one legacy path.** Advanced descriptors are not used, so the
  same code drives the 82540 and 82574 in QEMU.  **igb**-class adapters
  (e.g. `8086:10c9`) use a different advanced-descriptor model and are **not**
  bound here.

- **`pci-assign-bars` for onboard NICs.** A NIC behind a PCIe root port that
  firmware never configured has an unassigned BAR0 (reads back 0); the driver
  self-assigns BARs and opens bridge windows before mapping the register window.

- **TX bounded-wait + drop.** A TX slot the NIC has not released within 100 ms is
  dropped rather than overwritten.

- **`dma-alloc-32`.** Rings and buffers stay sub-4 GiB; the legacy descriptors'
  high address dword is written but is always 0.
